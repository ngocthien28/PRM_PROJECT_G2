# CampusHub — PRM393 Project Structure

This archive is a **project skeleton**, not a completed application. The complete `lib/` and `test/` file names come from Section 8 in `docs/specifications/00_CampusHub_Master_Coder_Implementation_Blueprint.docx`. This document overrides other architectural examples in case of conflicts.

## Start on Windows (VS Code / PowerShell)
1. Install Flutter SDK and Android SDK, then run `flutter doctor`.
2. Open this directory in VS Code.
3. Run `./scripts/setup_windows.ps1` (or execute each command manually).
4. Run `dart pub global activate flutterfire_cli`, then `flutterfire configure`. This **replaces** the placeholder `lib/firebase_options.dart`.
5. Set up Firebase Auth, Firestore, Storage, FCM and platform permissions/rules.
6. Run `flutter run` to see the temporary bootstrap screen.
7. Implement repositories, domain models, features and tests following file 00 and the agreed contracts.

## Important
- Current Dart feature files are TODO placeholders. No production authentication, registration, transaction, QR check-in or security rules are implemented.
- Android/iOS native platform files are generated by `flutter create`, not included here because they depend on the installed Flutter SDK. iOS builds require macOS.
- `firebase_options.dart` is not real configuration and must be regenerated.
- Dependency versions are deliberately resolved with `flutter pub add`, then **commit `pubspec.lock`**.
- Data path: View -> ViewModel/Provider -> Repository -> Firebase/REST/SQLite.
